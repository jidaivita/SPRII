# Collision JEPA J2 source and reader wrappers

These are the original J2 tuning and three-seed extension implementations, preserved with relocatable source paths. J2 uses Cross weight **0.3**, Align weight **0**, all-object replacement from epoch 1, source **50 epochs**, reader **100 epochs**, S3/query3, and paired source/reader seeds **0/1/2**. Seed 0 selects the recipe on full validation; seeds 1/2 repeat it without changing the selected settings. The [recipe](recipe.json) records this scientific configuration.

`jepa_train.py` is the original seed-0 tuning wrapper. `jepa_seed_train.py` is the hash-bound three-seed version. Both delegate to `../cophy_complete_v7/legacy/jepa_source.py`; the seed extension preserves its verified parent hash and checks the exact seed-parser substitution. The source is trained from random initialization rather than resuming another seed. `seeded_reader.py` changes only reader initialization/training streams, leaving donor and evaluation plans fixed. Its parent hash is rebound to the released reader after publication path anonymization; this release hash is not represented as the historical execution hash. `canonical_losses.py` preserves the actual optional alignment implementation. J2 disables that term.

Run from `benchmarks/cophy` after following its data/front-end preparation README. Set input paths to your prepared scientific assets. For each seed 0, 1, 2, source phases are:

```sh
python code/jepa_j2/jepa_seed_train.py prepare \
  --tune-cross 0.3 --tune-align 0 \
  --runtime-dir code/latent_v6_2_sig02 \
  --route-code code/collision_adapt_v6_4/source_route.py \
  --features data/features/collision \
  --relation-index data/prepared/collision/relation_index.json \
  --scene collision --method Cross --route all \
  --out runs/jepa_j2/seed0/source --device cuda:0 \
  --through 50 --threads 4 --seed 0
```

Repeat the same arguments with `smoke` and `train` instead of `prepare`; change both the seed and output directory for replicas. Source outputs include `checkpoint_50.pt`. For readers, use `seeded_reader.py --core code/cophy_complete_v7/common/readout.py --reader-seed 0` followed by the reader's `prepare`, `smoke`, `train`, `evaluate`, or `probe` command. Reader preparation supplies the base manifest, features, source checkpoint, `--model-code code/latent_v6_2_sig02/models.py --kind split --method Cross --source-epochs 50 --epochs 100 --supports 3`, plus output/device arguments. Use `--help` for each phase's full input contract. The reader's base, prepared evaluation inputs, and split plans must be generated by the common CoPhy preparation path.

The Native/Structure/Random controls use their preserved source-50 checkpoints and the common source-50/reader-100 evaluation; do not substitute their older source-100 comparison. General CPC/RSSM and control-seed replication uses [the preserved v9 seed runner](../replication_v9/seed_runner.py), with its parent-hash binding. This directory supplies the J2 scientific difference, not a new algorithm or a historical-result archive.
