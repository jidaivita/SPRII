# Frozen CoDA decoder and learned history encoders

This directory contains the final four-arm, three-seed encoder implementation and the corrected evaluation implementation (`coda_four_arm_eval_recovery_v2.py`). The adapted CoDA decoder stays fixed. The methods differ only in the history-encoder objective: plain prediction, same-system Cross, random-system Cross, and duplicate-self Cross.

## Interfaces and fixed budgets

A history has shape `[batch, 1, 401, 101]`, and the encoder returns a two-dimensional code consumed by the frozen CoDA decoder. A shared training-only teacher preparation runs 500 encoder updates at learning rate `3e-4`; every arm then runs 1,000 updates at `1e-4`. Cross weight is one and Align weight is zero. The native CoDA reference uses zero-initialized codes and 50 Adam support steps at `0.001`. The corrected evaluator reports zero-step encoder prediction as well as controlled code adaptation budgets. Seeds are 1234, 5678 and 9012.

- `coda_frozen_encoder.py`: history encoder, frozen decoder interface and loss components.
- `coda_frozen_encoder_gate.py`: shared preparation and encoder training/evaluation phases.
- `coda_four_arm_external.py`: fixed arm dispatch and donor permutation.
- `coda_four_arm_eval_recovery_v2.py`: final evaluation with the corrected immutable-decoder checks.

Source/data/checkpoint consistency checks are retained. The model's future target tensor is not an encoder input, and fixed-decoder evaluation checks the source network's parameter identity.

## Required inputs

Run from the repository root and fetch CoDA/GEPS/NOD dependencies using `scripts/fetch_external_sources.py`. The baseline code is in `benchmarks/baseline_adapters`. The replay requires each completed `coda_formal_three_seed/seedSEED` checkpoint, the matching training-only teacher `PROBE_CODES.npz`, and data bindings generated by that baseline. Shared pretraining outputs are required before arm training. The three source checkpoints, their derived teacher codes and historical metadata are not bundled here.

These scripts intentionally preserve the completed experiment's checkpoint and data fingerprints. They are the executed scientific implementation, not a generic from-scratch CLI that can replace missing source artifacts. For a fresh CoDA-to-Burgers experiment, start with the baseline component/data APIs; preserve the declared training, pairing, adaptation and final-evaluation budgets. A generic fresh-run wrapper and public weights are separate from this source snapshot.

`SPRII_ROOT` selects the repository and data root. All checked-in path defaults are public root-relative paths; no machine account, terminal URL or original file-server location is required to read this implementation.
