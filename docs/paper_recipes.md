# Paper training recipes

This is an English transcription of the **2026-09-25 manuscript snapshot**, Appendix B (Method and Experimental Implementation), with the current task protocols in Appendix C and selected released configurations. It covers the thirteen settings; the three CoPhy scenes and two NOD field systems count separately. It records methods and budgets, not experiment results or training logs.

A paper recipe, an implementation default, and a fully expanded executed-run configuration are different objects. Values explicitly described below as **code defaults** supplement the manuscript and are not evidence that every reported run used those defaults. Dataset, relation, continuation, source version, and reader conventions must be checked for the selected benchmark. The [configuration index](hyperparameters.md) is not an expanded run manifest. Fields absent from the current paper are identified rather than inferred from another benchmark.

## Common objective and controlled architecture

For paired persistent codes, `Align = 25 I + 25 V + C`, where `I` is mean squared alignment, `V` penalizes standard deviation below 1, and `C` penalizes off-diagonal covariance. Variance and covariance use sample denominator `n - 1`; epsilon is `1e-4`. Both related branches receive Align gradients. A disabled objective has zero weight. Prediction-target gradients follow each learner's own implementation.

The controlled D-Clean/PokeWorld recipe uses `Self + 0.02 SIGReg + 1.0 Align + 0.1 Cross` when both relation operations are enabled. SIGReg uses 17 quadrature knots and 1,024 random directions. Structure, Align-only, Cross-only, and Random relation controls retain their prescribed objective switches; do not add disabled terms. Current and persistent codes are each 64-dimensional. Histories contain 24 observations, with 32-dimensional action embeddings, a causal Transformer with 4 layers, width 192, 8 attention heads, and feed-forward width 768. The shared predictor has two hidden layers of width 256, a 128-dimensional context, future actions/masks, and a 32-dimensional horizon embedding. Prediction horizons are `{1, 4, 16}`. Native uses a monolithic 128-dimensional history representation.

The controlled source optimizer is AdamW: learning rate `3e-4`, weight decay `0.05`, 500-step warmup then cosine decay, gradient clipping `1.0`, bfloat16 autocasting, 20,000 updates. Each batch contains 48 systems / 96 donor-and-query windows. These values do not replace benchmark-specific SpringWorld, CoPhy, control, or field-model recipes.

## Benchmark-specific protocols

### SpringWorld

Use the preserved [native source layout](../benchmarks/springworld/README.md). Its donor history is **96 frames**, spanning 4.75 seconds, with 128×128 grayscale observations and causal frame differences. The first difference is zero. The cold-start query has no earlier motion history; the prediction interval is 0.8 seconds. Targets are eight-dimensional position/velocity increments standardized using training statistics. Physical ranges are mass `[0.5, 2]`, drag `[0.25, 1.5]`, stiffness `[4, 25]` in the manuscript's units.

There are 144 training systems and 178 development systems. The primary 100-system / 600-case reader panel and the 178-system / 16,020-case horizon panel are different populations. Frozen-source common readers train for **10,000 updates, batch 256**, with a 128-dimensional context, 64-dimensional persistent slot, and two 256-unit hidden layers. The main source/reader grid uses 3 source seeds and 3 reader seeds per source. Source and reader seed IDs and the reader learning rate are not enumerated in this manuscript profile; use the specific [Spring postrun recipe](../experiments/spring_postrun/README.md). Do not substitute the controlled 24-frame input or the separate residual-reader recipe.

Source normalization uses a fixed statistics snapshot during each update and updates statistics afterward from training history features. Readers and probes keep the source frozen. The compact prediction-decoupled comparator uses `Cross + 0.02 SIGReg` without Self or Align; Rel-InfoNCE uses fixed temperature `0.07`, 10,000 source updates, and the same three-source/three-reader evaluation design.

### D-Clean and PokeWorld

D-Clean is the analytically integrated system `dv/dt = F/m - gamma*v`, with mass `1`, time step `0.05`, 4D state observations, 8 independent 64-step interactions per system, and 1,000/200/200 train/validation/test systems. The independent-method comparison freezes NOD, CaDM, FCRL, and other sources before fitting the common downstream reader: 3 sources × 3 readers, **20,000 reader updates**, horizons `{1,4,16,32}`, and raw-state MSE on its separate 100-system report population. The selected DALI source has **160,000** updates and must not be labeled compute-matched to 20,000-update sources. Reader optimizer/batch and exact seed IDs should be read from the selected [baseline adapter](../benchmarks/baseline_adapters/README.md), not inferred from source training.

PokeWorld uses 64×64 images plus temporal differences, actions, and 4 independent 64-step rollouts per system. Its convolution channels are `32/64/128/256`, followed by a 128D projection and batch normalization. The factorized bank has `10 × 10 × 28` physical tuples, allocated as `20/4/4` stiffness tuples within each mass/drag block: 2,000/400/400 systems. Relations share mass; mass/drag; or mass/drag/stiffness. The full-system relation chooses among the other three rollouts. Random uses balanced system derangements. Fidelity levels are `{0, 0.5, 1}` with preserved marginals. The original and revision banks are distinct protocols: use the [revision manifest](../benchmarks/pokeworld/revision/PROTOCOL_MANIFEST.json) and [control configs](../configs/paper/poke_controls/) for revision runs. Do not mix their source modules silently.

### CoPhy Balls, Collision, and Blocktower

All three use three independent support histories (**S3**) and three initial query frames (**query3**). Prediction begins at query frame four: 27 target frames for Balls/Blocktower and 12 for Collision. The frozen official supervised perception front end supplies 784D visual features. Sources never receive physical labels or coordinate targets in the JEPA/CPC/RSSM route. The original supervised CoPhyNet objective is a separate route.

The main Collision comparison uses 1,994 held-out episodes and three joint source/reader seeds. **Every JEPA arm uses 50 source epochs**; CPC and RSSM use 100; each main reader uses 100 epochs. The paper does not give a single learning rate, batch, or relation-weight tuple covering every family and scene. Consult [CPC](../benchmarks/cophy/code/cophy_complete_v7/cpc/train.py), [RSSM](../benchmarks/cophy/code/cophy_complete_v7/rssm/train.py), and the selected JEPA/supervised source profile under [CoPhy code](../benchmarks/cophy/code/). CPC/RSSM implementations default to AdamW, batch 32, LR `3e-4`, weight decay `1e-4`; epoch defaults differ between source versions and must be overridden for the stated endpoint. In the preserved v7 source-0 entry points, CPC uses `--epochs 150 --stop-epoch 100`, RSSM uses `--epochs 100`, and [JEPA fixed-route source](../benchmarks/cophy/code/cophy_complete_v7/legacy/jepa_source.py) uses `--route all --through 50`. These base entry points enforce source seed 0. The preserved [v9 seed runner](../benchmarks/cophy/code/replication_v9/seed_runner.py) supplies the actual hash-bound seed extension for `cpc`, `rssm`, `mono`, `cross`, and `readout` kinds with seeds `{0,1,2}`. Run it with the SHA of the selected released parent file; publication path edits change a file hash without changing its algorithm. Its `--check-only` mode verifies the exact substitutions before execution. The selected Collision **J2** route additionally changes **Cross to 0.3 and Align to 0**, through the preserved [J2 source and seeded-reader wrappers](../benchmarks/cophy/code/jepa_j2/README.md); it uses source 50 / reader 100, S3/query3, all-object replacement, and paired seeds `{0,1,2}`. The [J2 recipe](../benchmarks/cophy/code/jepa_j2/recipe.json) records these overrides. Do not substitute the v7 default Cross weight 1 for J2.

Structured RSSM exports `U=[P64,h128,z32]` (224D), while Native exports its 160D recurrent state. Supervised CoPhyNet uses its original 32D code split into `P16/T16`, Align on `P16`, and Cross replacing `P16` while retaining the recipient state. The common reader sees the complete legal source state, not only its persistent slice. CPC candidates match public time/object slot/visible type. RSSM filters initial query frames with zero persistent input and Cross uses prior rollout. Balls/Collision use direct query-pose perception; Blocktower uses the cached-feature/pose-head path.

The older [policy_v3 configuration](../configs/cophy/policy_v3.json) describes a focal-substitution supervised protocol. It is **not** the expanded configuration of the current all-object Collision comparison. Do not derive the current main budgets or all-family weights from that historical policy.

### Baxter tactile and RH20T

Baxter uses 80×16 grasp-peak sequences, six shape/hardness configurations, and 170 grasps per configuration. The same grasp-ID permutation (seed `20260822`) is reused across configurations, split 110/30/30. Model histories contain 40 tactile samples and predict offsets `{1,20,40}`; input dimension is 16. Persistent encoding uses a 4-layer causal Transformer with 64D current and persistent codes. Donors are different grasps sharing hardness but changing shape, or sharing shape but changing hardness. Random deranges among the other five configurations. All world-model fits use final 10,000-update endpoints before the frozen confirmation evaluation. The released trainer fixes AdamW `3e-4`, weight decay `0.05`, Align `1`, Cross `0.1`; architecture and schedule are implemented in the trainer and [Baxter model](../src/persistent_jepa/baxter_model.py).

RH20T predicts normalized 6D force/torque and 3D TCP motion jointly with the latent objective. Relation identity is task identity, not known physical-parameter equivalence. Independent-episode, causal non-overlapping same-episode, random-group, visual, and low-dimensional conditions must retain their distinct input routes. The current paper describes 14 conditions × 3 seeds and a common checkpoint step; the released trainer defaults are listed in the table and do not constitute 42 expanded configs. In particular, seed IDs, enabled losses, donor route, and LowDim controls must be supplied for the specific condition. Use the [condition definitions](../src/persistent_jepa/rh20t_model.py), [preprocessing chain](../benchmarks/rh20t/README.md), and [data access guide](datasets.md). Training-only normalization and matching query/target/horizon/action are mandatory. The forecasting population has 25 held-out tasks; the 24-task hard-negative assay is separate.

### OvercookedV2, Articulated Swimmer, and Pendulum

Overcooked uses `grounded_coord_simple`, 20 training partners from ten partner-training sources, and two held-out development partners. Full/half/quarter data budgets contain 2,560/1,280/640 histories and 37,376,000/18,688,000/9,344,000 transitions. Every history consists of 146 recorded 100-step episode prefixes. The learning input retains two disjoint 100-step support episodes plus a 300-step query; the persistent slot is 32D. H+VC and H+SPRII share architecture, initialization, ordered batches, and the fixed 20,000-update endpoint. All 18 main fitted models are evaluated without optimizer updates. The native action loss already consumes the persistent route, so no extra Cross term is added. Use [paired configurations](../benchmarks/overcooked/configs/) for all budget/seed combinations.

Articulated Swimmer has three link masses and two joint damping parameters. The paper's fixed-weight assay changes own/wrong-system persistent input through each architecture's frozen source and predictor. The base S2R recipe in the table is not an adapter-training budget. The separate [masked-GRU architecture config](../benchmarks/swimmer/configs/masked_gru_cross_architecture_v1.json) uses base seeds `64101/64103`, a 128D history embedding, GRU hidden size 160, and persistent size 64. Its adapter seeds are `86101/86103/86107`, LR `1e-3`, weight decay `1e-4`, batch 1,024, minimum/maximum epochs `5/20`, patience `3`. The [delta-gated adapter](../benchmarks/swimmer/configs/articulated_delta_gated_isolation_v1.json) specifies AdamW. Verify the specific architecture's config and train-only normalization before rerunning; no single seed list describes every Swimmer analysis.

Pendulum selects R7 on development: Align weight `0.003`, variance target `0.1`, using the existing CaDM control interface. The released relation adapter fits 5 epochs after each collection iteration using batch 256, Adam `1e-3`, history/future lengths `10/10`. Its **outer collection budget is selected by the named profile**, so these per-fit epochs are not a total run budget. Evaluation uses three training seeds and ten 200-step episodes for ID and each of four OOD groups. Physical probes use the same checkpoints. Logged-action donor interventions do not establish an intervention on the online controller; see the [adapter guide](../benchmarks/baseline_adapters/README.md).

### NOD Burgers and FHN

Burgers uses independent trajectories sharing viscosity, with the recipient field as query. Source seeds are `1234/5678/9012`. The source manifest specifies batch 8, 200 epochs, LR `1e-4`, weight decay `1e-4`, gradient clip `1`, and 8,192 training query points; the released optimizer is AdamW. The selected relation weight is `0.03` from validation candidates `{0.01,0.03,0.1,0.3}`. Both initial source searches select checkpoints by ID development loss.

The current paper then continues SPRII with Align **zero**, for an additional **25/113/127 epochs** for the three source seeds respectively, at 45 updates per epoch. The final 25 epochs use LR `5e-5`. Continued NOD starts from its own selected checkpoints and receives the same additional updates. This matches continuation updates, not total ancestral training and search cost. The source manifest records the initial search; it is not the entire continuation chain. Preserve the selected parent checkpoint and optimizer/continuation arguments explicitly. See the [NOD guide](../benchmarks/nod/README.md).

FHN uses a regenerated Python simulation: periodic 128×128 fields, fourth-order spatial stencil, RK4 time step `0.001`, 101 saved frames through time 10, and independent-trajectory conditioning at frames `{0,25,50,75,100}`. Both learners use batch 8, RMSprop, initial LR `0.5/sqrt(P)` for trainable parameter count `P`, and LR multiplication by `0.95` every 500 updates. NOD prediction-only stages end at `20k/30k/40k/45k`. SPRII uses Align `0.01` with a 2k-update linear warmup through update 10k, followed by prediction-only stages ending at `30k/40k/50k`. After update 40k, both reset LR to `1e-5` while retaining RMSprop moments and scheduler state. Each continuation restarts its seeded sampling stream.

Seed 42 selects the recipes using ID mean relative L2 over horizons `{1,5,50}` on initial condition 5; seeds 43/44 repeat selected stages/endpoints. Report initial conditions are `{15,24,45}`. Budgets differ between the two methods. The released [minimal-closure JSON](../benchmarks/nod/configs/fhn_minimal_closure.json) describes an earlier one-seed development snapshot and **does not encode this full three-seed continuation recipe**. The current [three-seed selected configuration](../benchmarks/nod/configs/fhn_selected_three_seed.json) records the selected staged recipe. Use it with the released continuation entry point; record explicit overrides and parent checkpoints.

## Separate reader family

The residual realization readers are separate from SpringWorld's common 10,000-update reader. Their manuscript recipe uses frozen sources and a frozen 256-unit base, a 128-unit residual reader, MSE, AdamW, LR `1e-3`, batch 128, gradient clip `1`, and nominal 1,000-step base and route budgets with development-selected checkpoints. Context-amplitude changes happen after fitting; no source update occurs. Do not attach this reader recipe to every benchmark merely because it consumes a persistent code.
